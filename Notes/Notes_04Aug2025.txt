PLSQL stands for Procedural Language extension for SQL

what is missing in SQL? that PL/SQL gives us?
	if, switch, while, for
	variables, constants
	user defined functions or procedures
	throwing or catching errors
	

Certainly! Here's a **notepad-friendly comparison** showing what SQL can't do and how PL/SQL handles it — plain, clean, and ready to copy:

---

### 🔹 What SQL **Cannot** Do:

```sql
-- SQL Example (simple query)
SELECT * FROM CUSTOMERS WHERE CITY = 'Chennai';
```

This just fetches data.
But what if you want to process each row, apply conditions, update something, and handle errors?

You **can't** do that with plain SQL.

---

### 🔹 What PL/SQL **Can** Do:

```sql
-- PL/SQL Block Example
DECLARE
   v_name  VARCHAR2(100);
   v_credit NUMBER;
   CURSOR c1 IS
       SELECT NAME, CREDIT_LIMIT FROM CUSTOMERS WHERE CITY = 'Chennai';
BEGIN
   FOR rec IN c1 LOOP
       IF rec.CREDIT_LIMIT > 10000 THEN
           DBMS_OUTPUT.PUT_LINE('VIP Customer: ' || rec.NAME);
           -- You can UPDATE, INSERT, etc.
       ELSE
           DBMS_OUTPUT.PUT_LINE('Regular Customer: ' || rec.NAME);
       END IF;
   END LOOP;
EXCEPTION
   WHEN OTHERS THEN
       DBMS_OUTPUT.PUT_LINE('Something went wrong: ' || SQLERRM);
END;
/
```

---

### 🔹 Summary of What PL/SQL Adds:

* ✅ Variables: `DECLARE v_name VARCHAR2(100);`
* ✅ Loops: `FOR rec IN cursor LOOP ... END LOOP;`
* ✅ Conditions: `IF ... THEN ... ELSE ... END IF;`
* ✅ Exception Handling: `WHEN OTHERS THEN ...`
* ✅ Modularity: `Procedures`, `Functions`, `Packages`

CREATE OR REPLACE FUNCTION FNBONUS(EID INT)
RETURN NUMBER
AS
    CP NUMBER;
	SAL INT;
	BONUS NUMBER;
BEGIN
    SELECT SALARY, COMMISSION_PCT INTO SAL, CP 
    FROM HR.EMPLOYEES WHERE EMPLOYEE_ID=EID;

		CP:=0;
    END IF;
	BONUS:=SAL+(SAL*CP);

## ✅ **Corrected Version of Your Trigger**

```plsql
CREATE OR REPLACE TRIGGER trg1
AFTER INSERT ON SALES
FOR EACH ROW
DECLARE
    p INT;
    q INT;
BEGIN
    -- You can directly access :NEW.pid and :NEW.qty
    p := :NEW.pid;
    q := :NEW.qty;

    DBMS_OUTPUT.PUT_LINE('Trigger fired... PID: ' || p || ', QTY: ' || q);
END;
```

---

## 🔍 Explanation

| Part                        | Purpose                                                |
| --------------------------- | ------------------------------------------------------ |
| `AFTER INSERT ON SALES`     | Trigger fires after a new row is inserted into `SALES` |
| `FOR EACH ROW`              | Required to access `:NEW` and `:OLD` values            |
| `:NEW.pid`, `:NEW.qty`      | Values from the row being inserted                     |
| `DECLARE ... BEGIN ... END` | Proper PL/SQL block with variable declarations         |

---

### ✅ Example Insertion

```sql
INSERT INTO SALES (ID, PID, QTY) VALUES (6, 3, 2);
```

🔁 Output (if `DBMS_OUTPUT` is enabled):

```
Trigger fired... PID: 3, QTY: 2
```
