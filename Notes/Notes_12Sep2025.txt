S3 - Simple Storage Service

Steps to deploy a simple html,css,js website in S3 bucket and enable static web hosting.

To deploy an HTML file and its supporting images in AWS S3, follow these steps:

### 1. **Prepare Your Files**

* **HTML file**: Make sure your HTML file is ready, and any paths to images are correct.
* **Supporting images**: Ensure that the images are in a folder, and the links to these images in your HTML file point to the correct relative paths.

### 2. **Create an S3 Bucket**

* Go to the [AWS S3 Console](https://s3.console.aws.amazon.com/s3/home).
* Click on **Create bucket**.

  * Choose a globally unique name for your bucket.
  * Select the AWS region where you'd like to host the files.
  * Uncheck **Block all public access** (this will allow public access to your files).
  * Click **Create bucket**.

### 3. **Upload Your HTML and Images to S3**

* Open your newly created S3 bucket.
* Click on the **Upload** button.
* Upload the HTML file and the image folder (you can drag and drop the entire folder with all your images).
* After uploading, ensure the folder structure is intact in the S3 bucket (i.e., your images should be in the same folder path as they are in your local machine).

### 4. **Set Permissions for Public Access**

* You need to make the files publicly accessible. Go to the **Permissions** tab in the S3 bucket and:

  * In the **Bucket Policy**, add the following JSON policy (replace `your-bucket-name` with the actual bucket name):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::your-bucket-name/*"
    }
  ]
}
```

* This policy allows anyone to read files in the bucket.

### 5. **Enable Static Website Hosting**

* Go to the **Properties** tab of your S3 bucket.
* Scroll down to the **Static website hosting** section.
* Click **Enable**.
* For **Index document**, enter the name of your main HTML file (e.g., `index.html`).
* (Optional) For **Error document**, you can specify an error page (e.g., `error.html`).
* Click **Save changes**.

### 6. **Access Your Website**

* Once static website hosting is enabled, S3 will provide you with a **Bucket website endpoint**. It will look like:

```
http://your-bucket-name.s3-website-<region>.amazonaws.com
```

* Use this URL to access your website. If you have an `index.html` file, it should now be displayed in the browser.

---

### Troubleshooting:

* If your images are not showing up, ensure that:

  * The image paths in your HTML are relative to the S3 bucket's structure.
  * The S3 objects (images) are publicly accessible by checking the permissions.

That's it! You’ve now deployed your HTML website with supporting images on AWS S3.

Here’s a **complete step-by-step guide** to run your Docker image (`docker.io/jagindia/book-service:latest`) on **Amazon ECS (Elastic Container Service)** using **Fargate** (no EC2 servers needed).

---

## 🚀 Goal:

Run `docker.io/jagindia/book-service:latest` in **AWS ECS** using **Fargate**, via the AWS Console.

---

## ✅ Prerequisites:

* AWS account
* AWS CLI configured (optional, for CLI users)
* IAM permissions to use ECS, IAM, CloudWatch Logs, etc.
* A public Docker image (yours is from Docker Hub, so you're good)

---

## 🧭 Steps to Run the Docker Image on ECS (Fargate)

### **1. Create a VPC (if not already available)**

If you don't have a VPC, use the **VPC Wizard**:

* Go to **VPC > Your VPCs > Create VPC**
* Choose **VPC with Public Subnets**
* Name it something like `ecs-fargate-vpc`

---

### **2. Create a Cluster**

1. Go to **ECS > Clusters**
2. Click **Create Cluster**
3. Choose **Networking only (Fargate)**
4. Set:

   * **Cluster name**: `book-service-cluster`
5. Click **Create**

---

### **3. Create a Task Definition**

1. Go to **ECS > Task Definitions**
2. Click **Create new Task Definition**
3. Choose **Fargate**
4. Configure:

   * **Task Definition Name**: `book-service-task`
   * **Task Role**: Leave default or create a new one if needed
   * **Operating system**: Linux
   * **Task Size**:

     * CPU: `0.25 vCPU`
     * Memory: `0.5 GB` (or more as needed)

---

### **4. Add Container to the Task**

1. In the **Add container** section:

   * **Container name**: `book-service`
   * **Image**: `docker.io/jagindia/book-service:latest`
   * **Port mappings**:

     * Container port: `8080` (or whatever your app uses)

2. Optional: Enable logging

   * Choose **AWS Logs**
   * Set a log group name like `/ecs/book-service`
   * Create the group in **CloudWatch Logs** if needed

3. Click **Add** → then **Create** the task definition.

---

### **5. Run the Task in ECS Cluster**

1. Go to **ECS > Clusters > book-service-cluster**

2. Click **Run new task**

3. Set:

   * **Launch type**: Fargate
   * **Task Definition**: `book-service-task`
   * **Cluster**: `book-service-cluster`
   * **Platform version**: Latest
   * **VPC**: Select the VPC you created earlier
   * **Subnets**: Choose a public subnet
   * **Security Group**:

     * Allow **inbound access on port 8080** (or your app port)
     * Also allow outbound access to the internet

4. Click **Run Task**

---

### **6. Check Task Status**

* Go to **ECS > Clusters > book-service-cluster > Tasks**
* Wait for task to move from **PROVISIONING → PENDING → RUNNING**

---

### **7. Get Public IP and Access the App**

1. Click the running **task**
2. Scroll to the **"ENI" (Elastic Network Interface)** section
3. Copy the **public IP**
4. Access your app in the browser:

```
http://<public-ip>:8080
```

---

## 🔁 Optional: Expose via Load Balancer (for production)

* Create an **ECS Service** instead of running a standalone task
* Use **Application Load Balancer (ALB)** to get a public DNS name
* Set up **health checks, auto-scaling, and HTTPS** if needed

To **copy the public IP** of a running ECS task in **Fargate**, follow these steps from the **AWS Console**:

---

## ✅ Steps to Find & Copy Public IP of ECS Task

### 🔹 **1. Go to the ECS Console**

* URL: [https://console.aws.amazon.com/ecs](https://console.aws.amazon.com/ecs)
* Select the **region** where your ECS cluster is running (e.g., `ap-south-1` for Mumbai).

---

### 🔹 **2. Select Your ECS Cluster**

* Click on your cluster name (e.g., `book-service-cluster`).

---

### 🔹 **3. Go to the Tasks Tab**

* Scroll down to the **“Tasks”** section.
* Click on the **Task ID** of your **RUNNING** task.

---

### 🔹 **4. Find the ENI (Elastic Network Interface)**

* Scroll down to the **“Network”** section.
* Look for **“Elastic network interface”**.
* Click the **ENI ID link** (e.g., `eni-xxxxxxxx`) — it opens in the EC2 console.

---

### 🔹 **5. Get the Public IP in EC2 Console**

* In the **EC2 Console**, under the **“Description”** tab of the ENI, you'll see:

  * **Private IP**
  * **Public IPv4 address** ← ✅ **This is what you need**
* Click the **📋 copy icon** next to the Public IP to copy it.

---

### 🔹 **6. Access the App**

Open your browser and navigate to:

```
http://<public-ip>:<port>
```

For example:

```
http://3.108.56.123:8080
```

(Replace `8080` with the container port your app uses.)

---

## 🛑 If You Don’t See a Public IP

If the **public IP is missing**, check these:

| Issue                        | Fix                                                                              |
| ---------------------------- | -------------------------------------------------------------------------------- |
| Subnet is private            | Make sure you're using a **public subnet**                                       |
| No public IP assigned        | Modify the task's network config to **assign public IP = ENABLED**               |
| Security Group blocks access | Allow **inbound traffic** on the app port (e.g., 8080) in the **Security Group** |
