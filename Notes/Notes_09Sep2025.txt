Docker

🔹 What is Docker?

Docker is a tool that helps developers package applications and everything they need to run (code, libraries, system tools, settings) into something called a container.


🔹 Key Terms (in plain English)

Image – A blueprint for your application (like a recipe).

Container – A running instance of an image (like the finished dish).

Dockerfile – A file that tells Docker how to build an image (like a cooking instruction list).

Docker Hub – Like the App Store, but for Docker images.

🔹 Real-World Analogy

Without Docker: “It works on my machine 🤷‍♂️”

With Docker: “It works everywhere, every time ✅”

🔹 Why We Should Use Docker

Consistency – Runs the same on all machines (local, test, production).

Simplicity – No more “install this, configure that” — just run a container.

Isolation – Each app lives in its own world. No conflicts.

Portability – Move containers across machines or clouds easily.

Speed – Containers start super fast, saving development and deployment time.


docker commands:
----------------------

docker -v
docker images		lists all the images
docker image ls		lists all the images
docker ps			lists all the containers
docker container ls		lists all the containers
docker ps -a		lists all the containers including background
docker rm <<containerid>>	removes the container
				-f means forcibly
docker rmi <<imageid>>	removes an image
docker kill <<containerid>>
docker start
docker stop
docker pull		pull an image from hub.docker.com to local
docker run		run an image (so, it will become a container)
docker push		push an image from local to hub.docker.com
docker tag		tag a local image to a docker hub repository
docker build
docker network
docker compose up		to run the containers using docker compose file
