In the `WHERE` clause of a `SELECT` statement, you can use various **operators** to filter data. These operators fall into **categories**: **comparison**, **logical**, **range**, **pattern matching**, **null checking**, and **set membership**.

---

## 🔹 1. **Comparison Operators**

Used to compare values.

| Operator     | Description              | Example                     |
| ------------ | ------------------------ | --------------------------- |
| `=`          | Equal to                 | `WHERE PRICE = 100`         |
| `!=` or `<>` | Not equal to             | `WHERE CATEGORY <> 'Books'` |
| `>`          | Greater than             | `WHERE STOCK > 50`          |
| `<`          | Less than                | `WHERE PRICE < 500`         |
| `>=`         | Greater than or equal to | `WHERE PRICE >= 1000`       |
| `<=`         | Less than or equal to    | `WHERE STOCK <= 10`         |

---

## 🔹 2. **Logical Operators**

Combine multiple conditions.

| Operator | Description                         | Example                                          |
| -------- | ----------------------------------- | ------------------------------------------------ |
| `AND`    | Both conditions must be true        | `WHERE PRICE > 500 AND STOCK < 50`               |
| `OR`     | At least one condition must be true | `WHERE CATEGORY = 'Electronics' OR PRICE > 1000` |
| `NOT`    | Reverses a condition                | `WHERE NOT CATEGORY = 'Stationery'`              |

---

## 🔹 3. **Range Operator**

To check for a range of values.

| Operator              | Description                | Example                            |
| --------------------- | -------------------------- | ---------------------------------- |
| `BETWEEN ... AND ...` | Within a range (inclusive) | `WHERE PRICE BETWEEN 100 AND 1000` |

---

## 🔹 4. **Set Membership Operator**

To check if a value exists in a set.

| Operator   | Description               | Example                                     |
| ---------- | ------------------------- | ------------------------------------------- |
| `IN (...)` | Match any value in a list | `WHERE CATEGORY IN ('Electronics', 'Toys')` |

---

## 🔹 5. **Pattern Matching Operator**

Used to search with wildcards.

| Operator | Description                                | Example                             |
| -------- | ------------------------------------------ | ----------------------------------- |
| `LIKE`   | Pattern matching using `%` or `_`          | `WHERE NAME LIKE 'P%'`              |
| `%`      | Matches zero or more characters (wildcard) | `LIKE 'P%'` → names starting with P |
| `_`      | Matches a single character                 | `LIKE 'P_n'` → matches 'Pen', 'Pan' |

---

## 🔹 6. **Null Checking Operator**

Check for `NULL` values.

| Operator      | Description       | Example                      |
| ------------- | ----------------- | ---------------------------- |
| `IS NULL`     | Value is null     | `WHERE DISCOUNT IS NULL`     |
| `IS NOT NULL` | Value is not null | `WHERE DISCOUNT IS NOT NULL` |

---

## 🔹 7. **Existence Operator**

Check if subquery returns rows.

| Operator | Description                           | Example                             |
| -------- | ------------------------------------- | ----------------------------------- |
| `EXISTS` | Returns true if subquery returns rows | `WHERE EXISTS (SELECT 1 FROM ... )` |

---

## ✅ Summary Table

| Category             | Operators                             |
| -------------------- | ------------------------------------- |
| Comparison           | `=`, `!=`, `<>`, `>`, `<`, `>=`, `<=` |
| Logical              | `AND`, `OR`, `NOT`                    |
| Range                | `BETWEEN ... AND ...`                 |
| Set Membership       | `IN (...)`                            |
| Pattern Matching     | `LIKE`, `%`, `_`                      |
| Null Checking        | `IS NULL`, `IS NOT NULL`              |
| Existence (Subquery) | `EXISTS`, `NOT EXISTS`                |

## ✅ Rules for Using Subqueries in SQL

---

### 🔹 1. **Subqueries must be enclosed in parentheses**

```sql
SELECT * FROM EMPLOYEES 
WHERE DEPT_ID = (SELECT DEPT_ID FROM DEPARTMENTS WHERE DEPT_NAME = 'HR');
```

---

### 🔹 2. **Subquery must return only one column for scalar comparisons**

* Scalar subqueries (using `=`, `>`, `<`, etc.) must return **exactly one value**.

❌ Invalid:

```sql
SELECT * FROM EMPLOYEES 
WHERE DEPT_ID = (SELECT DEPT_ID, LOCATION FROM DEPARTMENTS); -- ❌ returns two columns
```

---

### 🔹 3. **Use `IN`, `ANY`, `ALL`, or `EXISTS` for multiple row results**

```sql
-- IN
SELECT * FROM EMPLOYEES 
WHERE DEPT_ID IN (SELECT DEPT_ID FROM DEPARTMENTS WHERE LOCATION = 'CHENNAI');

-- EXISTS
SELECT * FROM EMPLOYEES E
WHERE EXISTS (SELECT 1 FROM DEPARTMENTS D WHERE E.DEPT_ID = D.DEPT_ID);
```
this is called as "Correlated sub query"


---

### 🔹 4. **A subquery can be used in SELECT, FROM, or WHERE clause**

```sql
-- In SELECT clause
SELECT NAME, (SELECT DEPT_NAME FROM DEPARTMENTS WHERE DEPT_ID = E.DEPT_ID) AS DEPT
FROM EMPLOYEES E;	
--this is inline subquery

-- In FROM clause
SELECT AVG(SALARY) FROM (SELECT * FROM EMPLOYEES WHERE DEPT_ID = 10);
```

---

### 🔹 5. **Correlated subqueries use outer query values inside subquery**

```sql
SELECT NAME FROM EMPLOYEES E
WHERE SALARY > (
  SELECT AVG(SALARY) FROM EMPLOYEES WHERE DEPT_ID = E.DEPT_ID
);
```

> Correlated subqueries are evaluated **once per row** of the outer query.

---

### 🔹 6. **ORDER BY is not allowed in a subquery (except in `TOP`, `FETCH`, or `ROWNUM`)**

```sql
-- Valid with FETCH
SELECT * FROM (
  SELECT * FROM EMPLOYEES ORDER BY SALARY DESC
) WHERE ROWNUM = 1;
```

---

### 🔹 7. **Cannot use subquery in CHECK constraint**

```sql
-- This is not allowed:
CHECK (SALARY > (SELECT AVG(SALARY) FROM EMPLOYEES));
```

---

### 🔹 8. **Use aliases when subqueries appear in the FROM clause**

```sql
SELECT T.DEPT_ID, AVG(T.SALARY)
FROM (SELECT * FROM EMPLOYEES WHERE SALARY > 30000) T
GROUP BY T.DEPT_ID;
```

## 🧠 SQL `GROUP BY` Clause – Introduction

### 🔸 What is `GROUP BY`?

The `GROUP BY` clause in SQL is used to **group rows** that have the same values in one or more columns. It is often used **with aggregate functions** like `COUNT()`, `SUM()`, `AVG()`, `MAX()`, and `MIN()` to perform calculations **on each group**.

---

### 🔹 Syntax

```sql
SELECT column1, AGG_FUNCTION(column2)
FROM table_name
WHERE condition
GROUP BY column1;
```

---

### 🔹 Aggregate Functions Commonly Used

* `COUNT()` – Count rows
* `SUM()` – Total sum
* `AVG()` – Average value
* `MIN()` – Minimum value
* `MAX()` – Maximum value

---

### 🔹 Example Table: PRODUCTS

| ID | NAME     | CATEGORY    | PRICE  | STOCK |

JOINS
-----------------------------------
why we need join?
	whenever we need to retrieve data from multiple tables/ view/ sub queries, 
	we need to use joins.

ex:

Livesql HR schema has many tables including
	EMPLOYEES
	DEPARTMENTS

I want you to print 
	EMPLOYEE_ID
	FIRST_NAME
	DEPARTMENT_NAME
	

Note:
	DEPARTMENT_NAME is not present in the EMPLOYEES table.



SELECT EMPLOYEE_ID, FIRST_NAME, DEPARTMENT_NAME
FROM HR.EMPLOYEES, HR.DEPARTMENTS
WHERE HR.EMPLOYEES.DEPARTMENT_ID=HR.DEPARTMENTS.DEPARTMENT_ID;


The above join comes under:
	equi join
	inner join


equi join
	we use =	or != or any such comparison in join condition
	
inner join
	only matching rows are returned

we have used "comma" style join. The same we will try using "implicit" join syntax.

SELECT EMPLOYEE_ID, FIRST_NAME, DEPARTMENT_NAME, HR.EMPLOYEES.DEPARTMENT_ID
FROM HR.EMPLOYEES 
JOIN 
HR.DEPARTMENTS
ON HR.EMPLOYEES.DEPARTMENT_ID=HR.DEPARTMENTS.DEPARTMENT_ID;



A join is usually INNER JOIN

so matching rows only come.

one of the employee do not have department id so, it is not returned.

now, left outer join

SELECT EMPLOYEE_ID, FIRST_NAME, DEPARTMENT_NAME, HR.EMPLOYEES.DEPARTMENT_ID
FROM HR.EMPLOYEES LEFT JOIN HR.DEPARTMENTS
ON HR.EMPLOYEES.DEPARTMENT_ID=HR.DEPARTMENTS.DEPARTMENT_ID;

All records from left side table.
And matching rows from right side table.



SELECT EMPLOYEE_ID, FIRST_NAME, DEPARTMENT_NAME, HR.DEPARTMENTS.DEPARTMENT_ID
FROM HR.EMPLOYEES FULL JOIN HR.DEPARTMENTS
ON HR.EMPLOYEES.DEPARTMENT_ID=HR.DEPARTMENTS.DEPARTMENT_ID;
