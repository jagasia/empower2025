In the `WHERE` clause of a `SELECT` statement, you can use various **operators** to filter data. These operators fall into **categories**: **comparison**, **logical**, **range**, **pattern matching**, **null checking**, and **set membership**.

---

## 🔹 1. **Comparison Operators**

Used to compare values.

| Operator     | Description              | Example                     |
| ------------ | ------------------------ | --------------------------- |
| `=`          | Equal to                 | `WHERE PRICE = 100`         |
| `!=` or `<>` | Not equal to             | `WHERE CATEGORY <> 'Books'` |
| `>`          | Greater than             | `WHERE STOCK > 50`          |
| `<`          | Less than                | `WHERE PRICE < 500`         |
| `>=`         | Greater than or equal to | `WHERE PRICE >= 1000`       |
| `<=`         | Less than or equal to    | `WHERE STOCK <= 10`         |

---

## 🔹 2. **Logical Operators**

Combine multiple conditions.

| Operator | Description                         | Example                                          |
| -------- | ----------------------------------- | ------------------------------------------------ |
| `AND`    | Both conditions must be true        | `WHERE PRICE > 500 AND STOCK < 50`               |
| `OR`     | At least one condition must be true | `WHERE CATEGORY = 'Electronics' OR PRICE > 1000` |
| `NOT`    | Reverses a condition                | `WHERE NOT CATEGORY = 'Stationery'`              |

---

## 🔹 3. **Range Operator**

To check for a range of values.

| Operator              | Description                | Example                            |
| --------------------- | -------------------------- | ---------------------------------- |
| `BETWEEN ... AND ...` | Within a range (inclusive) | `WHERE PRICE BETWEEN 100 AND 1000` |

---

## 🔹 4. **Set Membership Operator**

To check if a value exists in a set.

| Operator   | Description               | Example                                     |
| ---------- | ------------------------- | ------------------------------------------- |
| `IN (...)` | Match any value in a list | `WHERE CATEGORY IN ('Electronics', 'Toys')` |

---

## 🔹 5. **Pattern Matching Operator**

Used to search with wildcards.

| Operator | Description                                | Example                             |
| -------- | ------------------------------------------ | ----------------------------------- |
| `LIKE`   | Pattern matching using `%` or `_`          | `WHERE NAME LIKE 'P%'`              |
| `%`      | Matches zero or more characters (wildcard) | `LIKE 'P%'` → names starting with P |
| `_`      | Matches a single character                 | `LIKE 'P_n'` → matches 'Pen', 'Pan' |

---

## 🔹 6. **Null Checking Operator**

Check for `NULL` values.

| Operator      | Description       | Example                      |
| ------------- | ----------------- | ---------------------------- |
| `IS NULL`     | Value is null     | `WHERE DISCOUNT IS NULL`     |
| `IS NOT NULL` | Value is not null | `WHERE DISCOUNT IS NOT NULL` |

---

## 🔹 7. **Existence Operator**

Check if subquery returns rows.

| Operator | Description                           | Example                             |
| -------- | ------------------------------------- | ----------------------------------- |
| `EXISTS` | Returns true if subquery returns rows | `WHERE EXISTS (SELECT 1 FROM ... )` |

---

## ✅ Summary Table

| Category             | Operators                             |
| -------------------- | ------------------------------------- |
| Comparison           | `=`, `!=`, `<>`, `>`, `<`, `>=`, `<=` |
| Logical              | `AND`, `OR`, `NOT`                    |
| Range                | `BETWEEN ... AND ...`                 |
| Set Membership       | `IN (...)`                            |
| Pattern Matching     | `LIKE`, `%`, `_`                      |
| Null Checking        | `IS NULL`, `IS NOT NULL`              |
| Existence (Subquery) | `EXISTS`, `NOT EXISTS`                |

## ✅ Rules for Using Subqueries in SQL

---

### 🔹 1. **Subqueries must be enclosed in parentheses**

```sql
SELECT * FROM EMPLOYEES 
WHERE DEPT_ID = (SELECT DEPT_ID FROM DEPARTMENTS WHERE DEPT_NAME = 'HR');
```

---

### 🔹 2. **Subquery must return only one column for scalar comparisons**

* Scalar subqueries (using `=`, `>`, `<`, etc.) must return **exactly one value**.

❌ Invalid:

```sql
SELECT * FROM EMPLOYEES 
WHERE DEPT_ID = (SELECT DEPT_ID, LOCATION FROM DEPARTMENTS); -- ❌ returns two columns
```

---

### 🔹 3. **Use `IN`, `ANY`, `ALL`, or `EXISTS` for multiple row results**

```sql
-- IN
SELECT * FROM EMPLOYEES 
WHERE DEPT_ID IN (SELECT DEPT_ID FROM DEPARTMENTS WHERE LOCATION = 'CHENNAI');

-- EXISTS
SELECT * FROM EMPLOYEES E
WHERE EXISTS (SELECT 1 FROM DEPARTMENTS D WHERE E.DEPT_ID = D.DEPT_ID);
```
this is called as "Correlated sub query"


---

### 🔹 4. **A subquery can be used in SELECT, FROM, or WHERE clause**

```sql
-- In SELECT clause
SELECT NAME, (SELECT DEPT_NAME FROM DEPARTMENTS WHERE DEPT_ID = E.DEPT_ID) AS DEPT
FROM EMPLOYEES E;	
--this is inline subquery

-- In FROM clause
SELECT AVG(SALARY) FROM (SELECT * FROM EMPLOYEES WHERE DEPT_ID = 10);
```

---

### 🔹 5. **Correlated subqueries use outer query values inside subquery**

```sql
SELECT NAME FROM EMPLOYEES E
WHERE SALARY > (
  SELECT AVG(SALARY) FROM EMPLOYEES WHERE DEPT_ID = E.DEPT_ID
);
```

> Correlated subqueries are evaluated **once per row** of the outer query.

---

### 🔹 6. **ORDER BY is not allowed in a subquery (except in `TOP`, `FETCH`, or `ROWNUM`)**

```sql
-- Valid with FETCH
SELECT * FROM (
  SELECT * FROM EMPLOYEES ORDER BY SALARY DESC
) WHERE ROWNUM = 1;
```

---

### 🔹 7. **Cannot use subquery in CHECK constraint**

```sql
-- This is not allowed:
CHECK (SALARY > (SELECT AVG(SALARY) FROM EMPLOYEES));
```

---

### 🔹 8. **Use aliases when subqueries appear in the FROM clause**

```sql
SELECT T.DEPT_ID, AVG(T.SALARY)
FROM (SELECT * FROM EMPLOYEES WHERE SALARY > 30000) T
GROUP BY T.DEPT_ID;
```

## 🧠 SQL `GROUP BY` Clause – Introduction

### 🔸 What is `GROUP BY`?

The `GROUP BY` clause in SQL is used to **group rows** that have the same values in one or more columns. It is often used **with aggregate functions** like `COUNT()`, `SUM()`, `AVG()`, `MAX()`, and `MIN()` to perform calculations **on each group**.

---

### 🔹 Syntax

```sql
SELECT column1, AGG_FUNCTION(column2)
FROM table_name
WHERE condition
GROUP BY column1;
```

---

### 🔹 Aggregate Functions Commonly Used

* `COUNT()` – Count rows
* `SUM()` – Total sum
* `AVG()` – Average value
* `MIN()` – Minimum value
* `MAX()` – Maximum value

---

### 🔹 Example Table: PRODUCTS

| ID | NAME     | CATEGORY    | PRICE  | STOCK |

views
-------
can we do DML on views?
	DML on views are allowed when that statement affects only columns of one underlying table.
	if we try to update data on a computed column, it is not allowed

Yes, ✅ **you can perform DML (INSERT, UPDATE, DELETE)** operations on **views**, but **with some rules and limitations**.

---

### ✅ **When DML on Views is Allowed:**

You **can perform DML** on a view if:

* The view is based on **a single base table**.
* The view does **not contain**:

  * `GROUP BY`
  * `DISTINCT`
  * `UNION`, `INTERSECT`, `MINUS`
  * `JOINs` (in general, unless it’s an **updatable join view**)
  * **Aggregate functions** (e.g., `SUM`, `AVG`)
* The view **includes all NOT NULL columns** of the base table (for INSERT).
* There are **no pseudocolumns** like `ROWNUM` in the view.

---

### ✅ **Examples of Allowed DML**

#### 1. **Base Table:**

```sql
CREATE TABLE EMPLOYEES (
  EMP_ID NUMBER PRIMARY KEY,
  NAME VARCHAR2(50),
  DEPT_ID NUMBER,
  SALARY NUMBER
);
```

#### 2. **Simple View:**

```sql
CREATE VIEW EMP_VIEW AS
SELECT EMP_ID, NAME, SALARY FROM EMPLOYEES;
```

#### 3. **Allowed DMLs:**

```sql
-- INSERT
INSERT INTO EMP_VIEW (EMP_ID, NAME, SALARY) VALUES (101, 'Alice', 50000);

-- UPDATE
UPDATE EMP_VIEW SET SALARY = 55000 WHERE EMP_ID = 101;

-- DELETE
DELETE FROM EMP_VIEW WHERE EMP_ID = 101;
```

---

### 🚫 **When DML is Not Allowed (Directly):**

DML fails when the view:

* Has **aggregations**, **grouping**, or **joins**
* Is based on **multiple tables**
* Excludes **required NOT NULL columns**

Example (Not allowed):

```sql
CREATE VIEW AVG_SALARY AS
SELECT DEPT_ID, AVG(SALARY) AS AVG_SAL FROM EMPLOYEES GROUP BY DEPT_ID;

-- UPDATE on AVG_SALARY → ❌ Not allowed
```

---

### ✅ **To Enable DML on Complex Views:**

Use **INSTEAD OF TRIGGERS**

```sql
CREATE VIEW COMPLEX_VIEW AS 
SELECT E.EMP_ID, E.NAME, D.DEPT_NAME
FROM EMPLOYEES E JOIN DEPARTMENTS D ON E.DEPT_ID = D.DEPT_ID;

-- Then create an INSTEAD OF trigger
CREATE OR REPLACE TRIGGER trg_instead_of_insert
INSTEAD OF INSERT ON COMPLEX_VIEW
FOR EACH ROW
BEGIN
  INSERT INTO EMPLOYEES (EMP_ID, NAME, DEPT_ID)
  VALUES (:NEW.EMP_ID, :NEW.NAME, 
     (SELECT DEPT_ID FROM DEPARTMENTS WHERE DEPT_NAME = :NEW.DEPT_NAME));
END;
/
```

```sql
CREATE VIEW AVG_SALARY_BY_DEPT AS
SELECT DEPT_ID, AVG(SALARY) AS AVG_SALARY
FROM EMPLOYEES
GROUP BY DEPT_ID;
```

### 🔹 **Q6. View with Filter Condition**

```sql
CREATE VIEW HIGH_SALARY_EMPLOYEES AS
SELECT NAME, SALARY FROM EMPLOYEES
WHERE SALARY > 50000;
```

### 🔹 **Q7. DML on View: Insert**

```sql
-- Insert into the high salary employees view
INSERT INTO HIGH_SALARY_EMPLOYEES (NAME, SALARY)
VALUES ('John Doe', 60000);
```

### 🔹 **Q8. DML on View: Update**

```sql
-- Update salary of an employee in the view
UPDATE HIGH_SALARY_EMPLOYEES
SET SALARY = 65000
WHERE NAME = 'John Doe';
```

### 🔹 **Q9. DML on View: Delete**

```sql
-- Delete an employee from the view
DELETE FROM HIGH_SALARY_EMPLOYEES WHERE NAME = 'John Doe';
```

### 🔹 **Q10. Invalid DML on Complex View**

```sql
CREATE VIEW DEPT_SALARY_SUM AS
SELECT DEPT_ID, SUM(SALARY) AS TOTAL_SALARY
FROM EMPLOYEES
GROUP BY DEPT_ID;

-- Attempting to update the view with aggregated data
UPDATE DEPT_SALARY_SUM SET TOTAL_SALARY = 500000 WHERE DEPT_ID = 1;
-- This will fail, because DML on aggregated views is **not allowed**.
```

---

## 🔍 **Explanation**

* **Q7**: **DML Allowed**: Inserts a new employee into the `HIGH_SALARY_EMPLOYEES` view.
* **Q8**: **DML Allowed**: Updates an employee's salary in the `HIGH_SALARY_EMPLOYEES` view.
* **Q9**: **DML Allowed**: Deletes an employee from the `HIGH_SALARY_EMPLOYEES` view.
* **Q10**: **DML Not Allowed**: Trying to **update a view with aggregated data** fails because aggregation (`SUM`) disallows DML operations on the view.
